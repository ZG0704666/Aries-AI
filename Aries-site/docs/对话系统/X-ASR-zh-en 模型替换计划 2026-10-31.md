# X-ASR-zh-en 模型替换计划（本地语音转文本 · 2026-10-31）

> 目标：将本地 ASR 引擎从 sherpa-ncnn（`streaming-zipformer-bilingual-zh-en-2023-02-13`）替换为 sherpa-onnx 生态的 **X-ASR-zh-en**（`x-asr-480ms/160ms-streaming-zipformer-transducer-zh-en-punct-int8-2026-06-05`，中英双语+内嵌标点，int8 ≈128MB，上游 Apache-2.0）。
> 前置阅读：《对话系统/离线ASR模型调研 2026-10-31》、《自动化引擎/语音与界面自动化优化方案 2026-10-31》（§1 选型依据）。
> 口径：行号基于 `test-capsule` HEAD `e2e5505`；本计划为实施蓝图，动手前需用户确认（涉及 native 依赖与 128MB 模型资产）。

## 1. 现有实现分析（替换前必须理解的 6 个事实）

| # | 事实 | 证据 | 对替换的含义 |
|---|---|---|---|
| 1 | 引擎通过**源码级 CMake** 构建：submodule `thirdparty/sherpa-ncnn`+`ncnn`，JNI 开启，依赖走 `ARIES_CMAKE_DEPS_CACHE` 本地缓存 | `app/src/main/cpp/CMakeLists.txt`（`ARIES_ENABLE_SHERPA_NCNN` option 已存在） | sherpa-onnx 官方推荐**预编译 so 放 jniLibs**，不走 app 侧 CMake——两条路并存不冲突，`ARIES_ENABLE_SHERPA_NCNN` 开关可平滑过渡 |
| 2 | Kotlin JNI 包装是**项目自有文件**（非 thirdparty）：`com.k2fsa.sherpa.ncnn.SherpaNcnn`，含项目扩展：幂等 close（R-06）、`isNativeLibraryReady()`/`nativeLibraryErrorMessage()` 探测 | `app/src/main/java/com/k2fsa/sherpa/ncnn/SherpaNcnn.kt` L68-72、L115-139 | onnx 侧包装必须**复刻这两个扩展**（崩溃防护与初始化错误提示依赖它们） |
| 3 | 进程内**单例识别器 + 引用计数**：`SherpaSpeechRegistry.attach/release`，双调用方（MainActivity 主页语音、AutomationViewModel 自动化语音）各持一票 | `speech/SherpaSpeechRegistry.kt` L58-86；`viewmodel/AutomationViewModel.kt` L1118/1167/1241/1262 | **Registry 与全部调用方 API 必须零改动**——替换只发生在 `SherpaSpeechRecognizer` 内部 |
| 4 | 并发模型是"会话执行器"：单线程串行（录音/解码/尾音排空/释放），会话代数丢弃迟到回调，cancel 不产 final | `SherpaSpeechRecognizer.kt` L136-150（不变量注释）、L721-805（runSession） | 该层与引擎无关，**原样保留**；仅替换其中的 native 调用点 |
| 5 | 自动标点目前由 **LLM 完成**：final 后发"标点助手"请求（会话代数绑定 R-10，编辑保护） | `MainActivity.kt` L3869-3954（prompt）、L4054-4068（消费）；AutomationViewModel 侧无标点 | **punct 模型自带标点后，LLM 标点链路可跳过**——这是本次替换最大的性能红利之一 |
| 6 | 模型资产契约：assets `sherpa-models/<dir>/` 7 文件，运行时 staging 拷贝 → 4 文件长度+SHA-256 清单（`.aries-model-manifest`）→ 原子 rename；模型不入库（`.gitignore`） | `assets/sherpa-models/README.md`；`ModelCacheManifest`（`SherpaSpeechRecognizer.kt` L58-128）；`createRecognizer()` L343-433 | 机制完全复用，仅改 modelDirName + requiredFiles 清单（7→4 文件） |

**当前数据流**：`AudioRecord(16k/mono/PCM16)` → `acceptSamples()`（L889）→ `while(isReady()) decode()`（L890-892）→ `text`/`isEndpoint()`（L894-895）→ partial/onResult 回调 → 松手：`ar.stop()` → `inputFinished()` → `while(isReady()) decode()` → `text` → 恰好一次 `onFinalResult`（L776-794）→ MainActivity：LLM 自动标点 → 回填/自动发送。

## 3. 接口适配方案

**原则：`SherpaSpeechRecognizer` 的公开面（构造、`initialize/isReady/isListening/startListening/stopListening/cancel/shutdown/lastInitializationError`、`RecognitionListener` 六回调）一字不改。** 引擎差异全部收敛在类内部，必要时抽 `private inner class Engine` 隔离，便于 A/B 回退。

### 3.1 API 映射表（ncnn → onnx）

| 现调用点（ncnn） | onnx 等价 | 备注 |
|---|---|---|
| `SherpaNcnn(config, assetManager=null)` | `OnlineRecognizer(assetManager=null, config=OnlineRecognizerConfig(...))` | transducer 三件套走 `OnlineTransducerModelConfig(encoder/decoder/joiner)` |
| `rec.reset(true)`（会话重建，L740） | `rec.reset(stream)`（新会话新建 `OnlineStream` 并替换旧引用） | onnx 以 stream 为状态载体；`runSession` 内 stream 随会话创建/丢弃，天然满足 R-05"不复用上一会话状态" |
| `rec.acceptSamples(samples)`（L889） | `stream.acceptWaveform(sampleRate, samples)` | 16k FloatArray 直传 |
| `while(rec.isReady()) rec.decode()`（L890-892） | `while(rec.isReady(stream)) rec.decode(stream)` | |
| `rec.isEndpoint()`（L894） | `rec.isEndpoint(stream)` | endpoint 规则参数在 `OnlineRecognizerConfig`（rule1/2/3 语义一致） |
| `rec.text`（L895/785） | `rec.getResult(stream).text` | **punct 版输出自带中文标点** |
| `rec.inputFinished()`（L781） | `stream.inputFinished()` | 尾音排空序列 `inputFinished → while(isReady) decode → getResult` 逐行对应（R-02 不变量保持） |
| 幂等 `close()`（R-06） | 包装层复刻同款 AtomicBoolean 模式 | |
| `enableEndpoint=false`（按住说话，L412） | 同参数置 false | 语义不变 |

### 3.2 会话不变量核对（R-02/03/05/06/08 全部可保持）

单线程会话执行器、代数丢弃、独占 AudioRecord、恰好一次终态、try/catch 收敛——全部位于 `SherpaSpeechRecognizer` 框架层，引擎替换不触碰。唯一注意点：`OnlineStream` 的创建须在会话任务线程内（与现在 `reset(true)` 位置对齐），禁止跨线程共享 stream。

## 4. 中英文识别能力的对接方式

1. **双语直接生效**：x-asr 为中英混训模型，`tokens.txt` 为中英混合词表——无需语言开关、无需双模型路由；`onPartialResult/onFinalResult` 透传即可，中英混说（如"打开 Wi-Fi"）由模型内部处理。
2. **标点双轨收敛**（关键适配）：punct 版 final 文本自带标点 → `applyAutoPunctuationIfNeeded`（MainActivity L3869）加短路：`rawText` 已含 `[。？！.?!]` 结尾或中间标点密度超阈值 → 直接透传，跳过 LLM 请求。收益：省一次网络往返（通常 0.5-2s）+ 离线可用性；`punctEpoch`/编辑保护逻辑（R-10）保持不动。保留"强制走 LLM 标点"设置开关作兜底（punct 输出风格不满意时可退回）。
3. **热词预留**：`OnlineRecognizerConfig.hotwordsFile/hotwordsScore` 参数位保留（与现 L416-417 对齐）；首期不启用，后续可喂联系人/应用名提升专名召回（与调研 §6.3-7 语料项对应）。
4. **延迟档位**：新增 `const val X_ASR_CHUNK_MS = "480ms"`（目录名拼接常量），480ms 起步（有第三方先例），160ms（首字更快）作 A/B 对照——只换目录常量即可切档。

## 6. 数据流和处理流程的调整

替换后数据流（粗体为变化点）：

```
AudioRecord 16k/mono/PCM16（不变）
 → 会话执行器线程：新建 OnlineStream（替代 reset(true)）
 → 循环：stream.acceptWaveform → while(isReady(stream)) decode(stream)
   → getResult(stream).text / isEndpoint(stream)（**文本已带标点**）
 → partial/onResult 派发（代数校验不变）
 → 松手：ar.stop() → stream.inputFinished() → 排空 decode → getResult → onFinalResult（恰好一次，不变）
 → MainActivity：**标点短路判断（新增）** → 回填/自动发送（不变）
 → 会话结束：stream 随会话丢弃；shutdown 时幂等 close recognizer（不变）
```

无新线程、无新队列；采集、限频（振幅 30Hz）、60s 上限、Registry 引用计数全部原样。

## 7. 潜在风险与兼容性问题

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 1 | **x86_64 so 缺失**导致模拟器语音不可用（abiFilters 含 x86_64，L82 注释明确模拟器依赖） | 高（阻塞冒烟） | 集成前先解包 release 验证两 ABI；缺失则 `build-android-x86_64.sh` 自编或 CI 产出 |
| 2 | **训练语料未披露**（Apache-2.0 为模型卡标注，语料链未审计） | 中（商用 gate） | 与调研文档 §5 审计流程合并；向作者提 issue 确认；在审计通过前保持"实验特性"定位或保留 ncnn 回退 |
| 3 | **低端机 RTF 未实测**（0.12 为桌面/产品级单线程参考） | 中 | A/B 判据沿用调研文档 §6.4（低端机 RTF ≤0.6）；不达标则降 160ms→480ms 或回退 |
| 4 | punct 标点风格与 LLM 标点不一致（用户已习惯旧风格） | 低 | 保留强制 LLM 标点开关；灰度期收集反馈 |
| 5 | onnxruntime so +15MB 对下载转化率的影响 | 低 | 一次性成本；ncnn 移除后净增 ≈+15MB（运行时口径），可接受性由用户拍板 |
| 6 | JNI 包装细节差异导致崩溃（如 close 后访问、异常跨 JNI） | 中 | 复刻 R-06 幂等模式；所有 native 调用保持会话线程内；`isNativeLibraryReady` 前置探测沿用 |
| 7 | 旧模型缓存与新清单不兼容（首次升级重拷 128MB） | 低 | 目录名不同→新目录独立 staging；旧目录异步清理；manifest 机制保证中断安全 |
| 8 | Kotlin API 文件与 so 版本不匹配（官方 kotlin-api 演进快） | 中 | **同一 release tag 取 so 与 kotlin-api**，写入 README 溯源表；升级时成对更新 |

## 8. 测试验证方案

1. **单元测试（无设备）**：
   - `ModelCacheManifest`：4 文件清单的 format/parse/坏行拒绝/长度校验用例更新（现有测试类扩展）；
   - 模型目录解析：三种 assets 布局候选逻辑回归；
   - 标点短路：`含标点→跳过 LLM`、`无标点→走 LLM` 的纯函数判断抽出可测。
2. **模拟器冒烟（AGENTS.md 已批准 AVD，`adb -s <serial>` 必带）**：
   - 冷启动初始化成功、`lastInitializationError` 为空；主页按住说话：partial 实时滚动（中文/英文/混说各 3 句）→ 松手 final 带标点 → LLM 标点被短路（日志断言）；自动化悬浮窗语音输入同链路验证（Registry 双调用方）；取消/60s 超时/权限拒绝三条异常路径。
3. **A/B 对比（真机，用户执行或授权后执行）**：按调研文档 §6.3 语料集（10 类×≥30 句）对比 ncnn 现役 vs x-asr-480ms vs x-asr-160ms，判据 §6.4（首字 ≤400ms P95、松手→final ≤300ms P95、低端机 RTF ≤0.6、10 分钟温升 ≤+8℃）。
4. **CI**：两新 so 存在性检查 + 全量 `:app:testDebugUnitTest` 保持全绿（当前基线 320/0）。
