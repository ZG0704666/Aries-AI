# 官网与文档站代码索引

> 本文是 `Aries-site/` 的维护入口。改首页、改文档、换截图、排查构建失败时，先看这里再动手。

## 站点组成

| 部分 | 目录 | 构建产物 | 部署 |
|------|------|----------|------|
| 官网 | `Aries-site/site/` | `dist/site/` | Cloudflare Pages → `https://aries-agent.com/` |
| 文档站 | `Aries-site/docs/` | `dist/docs/` | Cloudflare Pages → `https://docs.aries-agent.com/` |
| 构建脚本 | `Aries-site/scripts/` | 生成数据 / 兼容页 / 索引 | 随各站产物一起发布 |

两套站点由 `Aries-site/package.json` 的 npm workspaces 统一管理，根目录执行 `npm install` 一次即可。两站产物统一输出到 `Aries-site/dist/` 下的 `site/` 与 `docs/`，部署与本地预览路径对称。

```text
Aries-site/
├── package.json              # workspaces + 全部构建命令
├── dist/                     # 两站构建产物（gitignore；部署取这里）
│   ├── site/                 # 官网产物（Astro）
│   └── docs/                 # 文档站产物（VitePress）
├── site/                     # Astro 官网
│   ├── astro.config.mjs      # outDir 指向 ../dist/site
│   ├── public/               # 原样复制的静态文件（图标、_redirects、_headers、docs-center/）
│   └── src/
│       ├── assets/           # 需要 Astro 优化的图片
│       ├── components/       # 首页区块与通用组件
│       ├── data/             # 站点数据（版本、应用、截图）
│       ├── layouts/          # BaseLayout：SEO/OG/主题/统计
│       ├── pages/            # index / download / 404
│       └── styles/           # tokens.css + base.css
├── docs/                     # VitePress 文档站（同时是文档源目录）
│   ├── .vitepress/
│   │   ├── config.mts        # 路由改写、侧栏、导航、搜索、canonical（outDir 指向 ../dist/docs）
│   │   ├── links.ts          # 相对 .md 链接 → 英文 slug
│   │   ├── slugs.json        # 中文文件名 → 英文 URL
│   │   ├── categories.json   # 侧栏分组与顺序
│   │   ├── legacy-routes.json# 旧 hash 路由快照（生成一次）
│   │   ├── route-map.json    # 机器可读索引（生成）
│   │   └── theme/            # 主题、Mermaid 按需渲染、品牌样式
│   ├── public/               # favicon、robots.txt、llms.txt、route-map.json
│   └── **/*.md               # 68 篇技术文档（唯一文档源）
└── scripts/                  # 数据同步、兼容层、索引与校验（全部为 .mjs）
    ├── build-*.mjs           # 新站构建脚本
    ├── check-site.mjs        # 一致性校验
    ├── clean-output.mjs      # 清理 AppleDouble 文件
    └── lib/docs-data.mjs     # 文档/旧路由读取
```

## 官网（Astro）

### 页面与组件

| 文件 | 职责 |
|------|------|
| `site/src/layouts/BaseLayout.astro` | `<head>`、canonical、Open Graph、JSON-LD、主题预加载、Cloudflare 统计 |
| `site/src/pages/index.astro` | 首页组合：Hero → 服务商 → 能力 → 场景 → 应用墙 → 路线图 → CTA |
| `site/src/pages/download.astro` | 下载页：版本信息、三条下载线路、更新日志、安装步骤 |
| `site/src/pages/404.astro` | 404 页（Astro 输出 `404.html`，Cloudflare 用 `_redirects` 兜底） |
| `site/src/components/Nav.astro` | 顶部玻璃导航、移动端菜单、下载弹窗入口 |
| `site/src/components/Hero.astro` | 首屏文案、统计数字、三台手机预览 |
| `site/src/components/PhoneMock.astro` | 手机外壳 + 截图位；无图时渲染品牌占位 |
| `site/src/components/DownloadDialog.astro` | 全局下载弹窗（导航与首屏共用） |
| `site/src/components/FeatureGrid.astro` | 8 项核心能力卡片 |
| `site/src/components/Spotlight.astro` | 虚拟屏 / 离线语音两个重点场景 |
| `site/src/components/AppWall.astro` | 52 个已适配应用图标墙 |
| `site/src/components/Roadmap.astro` | 已上线 / 进行中路线图 |
| `site/src/components/Footer.astro` | 页脚导航与联系方式 |
| `site/src/components/Starfield.astro` | 深空背景（极光 + 星点） |
| `site/src/components/ThemeToggle.astro` | 深色 / 浅色切换 |
| `site/src/styles/tokens.css` | 品牌色、玻璃质感、间距、圆角、明暗主题变量 |
| `site/src/styles/base.css` | 全局重置、容器、按钮、卡片、通用动效 |

样式约定：颜色、圆角、阴影一律走 `tokens.css` 变量；组件样式写在 `.astro` 文件的 `<style>` 内，不引入 Tailwind 或第三方 UI 库。

### 数据文件

| 文件 | 说明 |
|------|------|
| `site/src/data/site.generated.json` | 正式版（GitHub Release）、开发版版本号、QQ 群、GitHub 地址；由 `npm run build:data` 更新 |
| `site/src/data/apps.json` | 52 个应用名称与图标路径（图标在 `site/public/icons/apps/`） |
| `site/src/data/screenshots.ts` | 首页三张截图的槽位配置 |

### 换首页截图

1. 把图片放进 `site/src/assets/screenshots/`（建议宽度 840px 以上，9:19.2 竖图）。
2. 在 `site/src/data/screenshots.ts` 里给对应槽位补 `src`（`import` 后传入，交给 Astro 优化）与 `alt`。
3. `PhoneMock.astro` 会自动从占位态切换为真实截图，无需改页面。

## 文档站（VitePress）

### 路由：中文文件名 → 英文 URL

- 文档源保持 `Aries-site/docs/<中文目录>/<中文标题>.md`，不重命名、不复制。
- `docs/.vitepress/slugs.json` 维护 `相对路径（无 .md） → 英文 slug`，VitePress 通过 `rewrites` 输出 `/{slug}`。
- `docs/.vitepress/categories.json` 维护 15 个侧栏分组及顺序（含 `legacy` 兼容入口）。
- 新增文档必须同时更新两个 JSON，否则 `npm run check` 会失败。

### 旧链接兼容

| 旧地址 | 处理方式 |
|--------|----------|
| `/docs-center.html#/overview-intro` | Pages 自动归一化到 `/docs-center`，跳转壳读取 hash，替换为新站 slug |
| `/docs-center` | `site/public/docs-center/index.html` 目录形式直接静态服务（不要用 `.html` 目标做重写，会触发 Pages 去后缀归一化形成 308 自循环） |
| `/docs/技术架构/整体架构设计.md` | `_redirects` 301 到 `https://docs.aries-agent.com/architecture/overview` |
| 已删除的 4 篇语音文档 | 统一跳到 `chat/input-waveform`，避免 404 |

跳转壳与 `_redirects` 都由 `scripts/build-legacy.mjs` 生成，不要手改。旧路由数据在首次生成时冻结到 `docs/.vitepress/legacy-routes.json`；仓库根部旧静态站文件（`Aries-site/index.html`、`Aries-site/docs-center.html`、`Aries-site/assets/`、`Aries-site/styles/`、旧 `scripts/*.js`、遗留 `build/` 目录）已删除，不再参与构建和部署。

### Mermaid

192 张图不参与构建期渲染：markdown 里保留 ` ```mermaid ` 代码块，浏览器端由 `docs/.vitepress/theme/mermaid.ts` 用 `IntersectionObserver` 按需加载 `mermaid`，滚动到附近才渲染；深浅色切换时自动重绘。无 JS 时仍能看到原始代码块。

### 搜索

使用 VitePress 本地搜索（MiniSearch）。中文没有空格，`config.mts` 里的 `tokenize` 会把 CJK 文本切成单字 + 双字组合，英文/数字保持整词，避免整段中文变成一个 token。

## 构建脚本

| 命令 | 作用 |
|------|------|
| `npm install` | 安装两个 workspace 的依赖（根目录执行一次） |
| `npm run build` | 全量构建：数据 → 兼容层 → llms.txt → 路由索引 → 官网 → 文档站 → 清理产物 |
| `npm run build:data` | 拉取 GitHub 最新 Release，读取 Gradle 开发版号，写 `site.generated.json` |
| `npm run build:legacy` | 生成 `site/public/docs-center/index.html` 与 `_redirects` |
| `npm run build:llms` | 生成 `docs/public/llms.txt` |
| `npm run index` | 生成 `docs/.vitepress/route-map.json` 与 `docs/public/route-map.json` |
| `npm run check` | 校验 slug 覆盖、侧栏完整性、文档死链、HTML 标签闭合、图标与版本字段 |
| `npm run build:clean` | 清理 macOS 在 NTFS / exFAT 卷上生成的 `._*` 文件 |
| `npm run dev:site` | 本地调试官网（Astro） |
| `npm run dev:docs` | 本地调试文档站（VitePress） |
| `npm run preview:site` / `preview:docs` | 预览构建产物 |

`build:data` 在无网络时会保留已有版本数据并打印警告，不阻塞构建；需要强制离线构建时加 `--offline`。

## 机器可读索引

`docs/.vitepress/route-map.json`（对外副本 `docs/public/route-map.json`）包含：

- `docs[]`：`file`、`title`、`slug`、`url`、`source`
- `categories[]`：侧栏分组与条目
- `legacyRoutes{}`：旧 hash 路由 id → 新 slug
- `removedDocs[]`：已删除文档及其回退目标

需要让脚本或 AI Agent 定位文档时，读这个文件，不要解析 `config.mts`。

## 部署

两个 Cloudflare Pages 项目，构建命令都在 `Aries-site/` 下执行：

| 项目 | Root directory | Build command | Output directory |
|------|----------------|---------------|------------------|
| 官网 | `Aries-site` | `npm run build:site` | `dist/site` |
| 文档 | `Aries-site` | `npm run build:docs` | `dist/docs` |

Direct Upload 方式则分别拖入 `dist/site` 与 `dist/docs` **里面的文件**（不要多套一层目录）。

注意事项：

- 两个项目都需要先执行 `npm install`；Node 版本 20 以上。
- 现有 Cloudflare 项目如果仍把输出目录指向 `Aries-site/`（旧静态站），必须改成上表的 Root directory + Build command + Output directory，否则线上仍是旧页面。
- `docs.aries-agent.com` 需要在 Cloudflare DNS 里添加 CNAME 指向 Pages 项目。
- 官网 `_headers` 负责安全响应头与静态资源缓存；文档站同理。
- 构建前建议在 CI 里跑 `npm run check`，死链会直接让流水线失败。
- 旧路由快照 `docs/.vitepress/legacy-routes.json` 只生成一次；如果以后还要兼容新的旧 id，删除该文件后重新运行 `npm run build:legacy`。

## 常见修改速查

| 想改什么 | 改哪里 |
|----------|--------|
| 首页文案 / 首屏 | `site/src/pages/index.astro`、`site/src/components/Hero.astro` |
| 能力卡片 | `site/src/components/FeatureGrid.astro` |
| 应用墙 | `site/src/data/apps.json` + `site/public/icons/apps/` |
| 下载线路 / 安装步骤 | `site/src/pages/download.astro`、`site/src/components/DownloadDialog.astro` |
| 品牌色 / 明暗主题 | `site/src/styles/tokens.css` |
| 文档侧栏顺序 | `docs/.vitepress/categories.json` |
| 文档 URL | `docs/.vitepress/slugs.json` |
| 文档首页 | `docs/index.md` |
| 文档站品牌样式 | `docs/.vitepress/theme/custom.css` |
| 版本号 | `npm run build:data`（自动读 GitHub + Gradle） |

## 约定

- 文档只存一份：`Aries-site/docs/`，不要在仓库根目录再建 `docs/`。
- 新增或删除文档后，同步 `slugs.json`、`categories.json`，再跑 `npm run index && npm run check`。
- 文档内相对链接必须指向真实文件；指向仓库根目录文件（如 `README.md`）时优先用 GitHub 绝对地址。
- 站点不引入第三方字体与 CDN 样式，保持可直接部署的静态产物。
